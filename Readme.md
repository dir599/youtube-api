# YouTube API — Backend

A RESTful backend API for a YouTube-like video platform built with **Node.js, Express.js, Prisma ORM, and PostgreSQL**.

The API handles user authentication, video management, subscriptions, watch history, and media uploads. Authentication is implemented using **JWT access and refresh tokens**, with refresh tokens stored securely in the database.

* User registration and login

* Access token and refresh token system

## 🔐 Authentication

Authentication uses **JWT** with two tokens:

### Access Token

The access token is used to authenticate requests to protected routes.

It contains the user's ID and is verified by the authentication middleware.

Example:

```http
Authorization: Bearer <access_token>
```

The backend can also read the access token from cookies.

### Refresh Token

The refresh token is used to generate a new access token after the access token expires.

The refresh token is stored in the database and can also be stored in an HTTP-only cookie.

The database stores the refresh token, but the short-lived access token does not need to be stored in the database.

## 🔑 Authentication Flow

```text
Register
   ↓
Hash Password
   ↓
Create User
   ↓
Login
   ↓
Verify Email + Password
   ↓
Generate Access Token
   ↓
Generate Refresh Token
   ↓
Send Tokens
   ↓
Access Protected Routes
```

Protected requests are handled by JWT verification middleware:

```text
Request
   ↓
JWT Middleware
   ↓
Verify Token
   ↓
Find User
   ↓
Attach User to req.user
   ↓
Controller
   ↓
Service
   ↓
Database
```

## 👤 User API

### Register

```http
POST /auth/register
```

Creates a new user account.

Example request:

```json
{
  "username": "john",
  "email": "john@example.com",
  "password": "password123",
  "fullName": "John Doe"
}
```

### Login

```http
POST /auth/login
```

Authenticates the user and generates JWT tokens.

Example:

```json
{
  "email": "john@example.com",
  "password": "password123"
}
```

### Logout

```http
POST /auth/logout
```

Logs the user out and clears the stored refresh token.

### Get Current User

```http
GET /auth/me
```

Requires authentication.

### Update Account

```http
PATCH /auth/update-account
```

Updates account information such as username or email.

### Change Password

```http
PATCH /auth/change-password
```

Changes the authenticated user's password.

## ☁️ Cloudinary

Media files such as:

* User avatars
* Cover images
* Video thumbnails
* Videos

can be uploaded to **Cloudinary**.

The typical upload flow is:

```text
Client
  ↓
Multer
  ↓
Temporary File
  ↓
Cloudinary
  ↓
Cloudinary URL
  ↓
PostgreSQL
```

Only the media URL is stored in the database rather than storing the actual media file inside PostgreSQL.

## 📤 File Uploads

Multer is used to process multipart/form-data requests.

Temporary files are stored inside:

```text
public/temp/
```

They are then uploaded to Cloudinary.

## 🧱 Architecture

The project follows a **Controller-Service architecture**.

```text
Route
  ↓
Middleware
  ↓
Controller
  ↓
Service
  ↓
Prisma
  ↓
PostgreSQL
```

### Routes

Routes define the API endpoints and middleware.

### Controllers

Controllers handle:

* Request data
* Response status
* Calling services

### Services

Services contain the main business logic and database operations.

For example:

```js
const user = await prisma.user.findUnique({
  where: {
    email,
  },
});
```

This separation keeps the application easier to maintain and scale.

## ⚙️ Environment Variables

Create a `.env` file in the backend root:

```env
PORT=3000

DATABASE_URL="postgresql://username:password@localhost:5432/youtube"

CORS_ORIGIN=http://localhost:5173

ACCESS_TOKEN_SECRET=your_access_token_secret
ACCESS_TOKEN_EXPIRY=15m

REFRESH_TOKEN_SECRET=your_refresh_token_secret
REFRESH_TOKEN_EXPIRY=7d

CLOUDINARY_CLOUD_NAME=your_cloud_name
CLOUDINARY_API_KEY=your_api_key
CLOUDINARY_API_SECRET=your_api_secret
```

**Never commit your `.env` file to GitHub.**

Add it to `.gitignore`:

```gitignore
.env
node_modules/
public/temp/
```

## 🔒 Security

The API implements several security practices:

* Passwords are hashed using bcrypt.
* JWT secrets are stored in environment variables.
* Authentication middleware protects private routes.
* Refresh tokens are managed separately from access tokens.
* CORS is configured for the frontend.
* Sensitive environment variables are not committed to Git.
* Users can only modify resources they are authorized to access.

## 🌐 Frontend Integration

The frontend can communicate with this API using the backend URL stored in an environment variable.

Example:

```env
VITE_BACKEND_URL=http://localhost:3000
```

For requests that use authentication cookies:

```js
fetch(`${import.meta.env.VITE_BACKEND_URL}/auth/login`, {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
  },
  credentials: "include",
  body: JSON.stringify({
    email,
    password,
  }),
});
```

The backend CORS configuration must allow credentials:

```js
cors({
  origin: process.env.CORS_ORIGIN,
  credentials: true,
});
```
